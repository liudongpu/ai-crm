# LexDesk · 律所管理平台

面向律师事务所的核心运营管理系统，参考 Clio 的 Manage / Grow 理念，覆盖从咨询线索、利益冲突检查、案件承办，到日历截止日期、文档、时间费用、账单收款、信托与经营分析的完整链路。

## 技术栈

| 层 | 技术 |
| --- | --- |
| 后端 | NestJS 12 + TypeORM 0.3 + SQLite（better-sqlite3） |
| 前端 | React 19 + TypeScript + Vite 8 + Material UI 7 + Emotion |
| 图表 | Recharts |
| 拖拽 | dnd-kit |
| 数据请求 | TanStack Query |

## 目录结构

```
apps/
├── api/    # NestJS API，默认 http://localhost:3000/api
└── web/    # React 前端，开发模式默认 http://localhost:5173
data/       # SQLite 数据库文件（首次启动自动创建并写入演示数据）
doc/
├── prod.md # Clio 律所平台功能分析参考
└── todo.md # 任务与完成记录
```

## 本地运行

```bash
npm install
npm run dev
```

- 前端：http://localhost:5173
- 接口：http://localhost:3000/api

也可以分别启动：

```bash
npm run dev:api
npm run dev:web
```

## 生产模式

生产模式会自动构建前后端，并由 API 同源提供前端页面：

```bash
npm run start
```

然后访问 http://localhost:3000 。也可以先执行 `npm run build`，再运行：

```bash
npm run start:prod -w @ai-crm/api
```

## 功能模块

系统按 `doc/prod.md` 组织为 **12 个一级功能、82 个二级功能**：顶部导航切换一级功能，左侧 Sidebar 展示当前一级功能下的全部二级功能。

| 一级功能 | 二级功能 |
| --- | --- |
| 获客与客户关系管理 Grow | 线索与CRM、获客intake、资格筛查、冲突检查、预约与跟进、签约转化、营销、口碑与复购 |
| 案件与事项管理 Manage | 案件档案、自定义数据、任务与流程、案件流程模板、冲突与检索、活动时间线、移动与访问 |
| 日历、任务与截止日期 | 日历管理、截止日期计算、时效管理、AI日历辅助、同步与提醒、日历与计费联动 |
| 文档管理与文档自动化 Draft | 文档存储与管理、模板自动化、法院表格、电子签名、协作与版本、Word集成 |
| 客户沟通与客户门户 | 统一沟通、邮件归档、客户门户、自动跟进、电话与会议、客户自助 |
| 时间、费用与计费 | 时间记录、费用记录、费率与计费模式、账单生成、发票与发送、电子账单、应收与催收、计费审批 |
| 支付、信托与法律会计 | 在线支付、支付计划、信托会计、对账、总账会计、财务报表、应付与支出、会计协作 |
| 实体法律工作AI Work | 案件分析、法律检索、策略检验、起草、文档审阅、引用与验证、权限继承 |
| 报告、分析与经营管理 | 律所仪表盘、核心经营指标、自定义报告、获客报告、财务报告、AI洞察、审计与可追溯 |
| 自动化、工作流与AI运营 | 工作流、AI运营辅助、AI沟通辅助、任务自动化、计费自动化、营销自动化 |
| 集成生态与开放能力 | 邮件与日历、会计、文档与存储、沟通与会议、自动化与开放API、执业领域应用、银行与信用卡同步 |
| 安全、合规与治理 | 认证与加密、合规框架、AI数据政策、访问控制、账户安全、治理 |

已有成熟页面（案件、客户、联系人、线索、日历、文档、沟通、计费、信托、报表等）继续提供完整业务操作；其余二级功能由统一的“功能记录”页面承载，支持筛选、新建、编辑、删除、详情与状态流转。

> 集成生态、法律工作 AI、安全合规等模块为本地演示能力，用于配置、记录和跟踪，不代表已完成真实第三方对接、法律 AI 推理或认证审计。

首次启动时，后端会自动创建 `data/crm.sqlite` 并填充律师、客户、联系人、案件阶段、案件、线索、任务、文档、时间费用、账单、支付、信托交易、沟通、备注，以及 12 个功能目录、82 个二级功能及其演示记录。删除该文件后重启即可重置。
