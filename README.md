# LexDesk · 律所管理平台

面向律师事务所的核心运营管理系统，参考 Clio 的 Manage / Grow 理念，覆盖从咨询线索、利益冲突检查、案件承办，到日历截止日期、文档、时间费用、账单收款、信托与经营分析的完整链路。

## 技术栈

| 层 | 技术 |
| --- | --- |
| 后端 | NestJS 12 + TypeORM 0.3 + SQLite（better-sqlite3） |
| 前端 | React 19 + TypeScript + Vite 8 + Material UI 7 + Emotion |
| 图表 | Recharts |
| 拖拽 | dnd-kit |
| 数据请求 | TanStack Query |

## 本地运行

```bash
npm install
npm run dev
```

- 前端：http://localhost:5173
- 接口：http://localhost:3000/api

也可以分别启动：

```bash
npm run dev:api
npm run dev:web
```

## 生产模式

生产模式会自动构建前后端，并由 API 同源提供前端页面：

```bash
npm run start
```

然后访问 http://localhost:3000 。也可以先执行 `npm run build`，再运行：

```bash
npm run start:prod -w @ai-crm/api
```

## 功能模块

系统参照 `doc/Law-Firm-OS-5-10-People-Complete-With-Communication.md` 重组为 **8 个业务模块 + 其他（共 9 个一级模块、62 个二级功能）**。默认首页为「我的工作台」（`/`）：案件看板按阶段泳道展示，拖拽卡片即可更新案件阶段（已归档泳道仅显示最近 10 条）；原统计仪表盘移到 `/dashboard`。顶部导航切换一级模块，左侧 Sidebar 展示当前模块下的二级功能。旧的 12/82 结构已合并精简，不再保留。

| 一级模块 | 二级功能 |
| --- | --- |
| 工作台 | 我的工作台（默认页，案件阶段泳道看板，可拖拽）、日程（日/周/月/列表视图，点击日期或时间格快速新建）、经营仪表盘、核心报表、自定义报告 |
| 获客客户 | 线索管理、客户档案、联系人、冲突审查、咨询预约、签约转化、客户门户 |
| 案件中心 | 案件档案、任务与流程、日历管理、截止日期计算、时效管理、AI日历辅助、同步与提醒、日历计费联动、文档管理、电子签名 |
| 法律AI | 卷宗智能解析、法规类案检索、智能文书起草、合同智能风控、AI洞察、行政事务助手（6 项均为独立专用页面） |
| 律师工具箱 | 诉讼执行计算器、利息测算器、赔偿测算器、诉讼期限推算器、证据文档处理、企业工商失信速查（6 项均为独立专用页面，结果可一键保存到当前案件） |
| 计费财务 | 时间记录、费用记录、费率与计费模式、账单与发送、应收与催收、收款与支付计划、信托会计、对账、总账与报表 |
| 设置安全 | 人员与角色、角色权限、案例分类（分类与流程模板）、安全与合规、访问控制、AI数据政策、审计追溯 |
| 沟通中心 | 统一收件箱、电话与会议、自动跟进 |
| 其他 | 营销与转介绍、移动与访问、Word集成、工作流、任务自动化、计费自动化、集成配置、执业领域应用、银行同步 |

62 个二级功能全部为真实可用页面，**不保留通用“功能记录”占位页**：

- **24 个核心业务功能**由成熟业务页面承载：工作台/日程/报表、线索/客户/联系人、案件/任务、6 项日历、文档、统一收件箱、时间/费用/账单/信托、设置与角色权限等。「日程」（`/schedule`）位于工作台模块，参照 Lex Passage 活动日历提供日/周/月/列表视图、按日历/类型/负责人/时间/状态筛选、点击日期或时间格快速新建、日程详情与完成/编辑/删除操作。「案例分类」（`/settings?tab=categories`）参照 Lex Passage「Matter types · Flows」，在设置页维护案件分类（与案件业务领域对应）及每类案件的默认办理阶段模板，支持新增/编辑/停用分类、阶段顺序与结案阶段调整；模板仅作用于之后新建的案件。
- **26 个二级功能**由后端「可扩展工作台」（`/api/workspace`）驱动：每个功能有专属字段 schema、状态机、统计口径与本地配置开关，前端渲染为 `/workspace/<编码>` 独立页面，具备筛选、分页、新建、编辑、删除、详情、状态流转、统计卡片与配置持久化。「其他」模块以此承载。
- **6 个法律AI功能**为独立专用页面（仍使用原有 `/workspace/<编码>` 路由与功能目录编码，因此功能总数不额外增加）：卷宗智能解析、法规类案检索、智能文书起草、合同智能风控、AI洞察、行政事务助手；由后端 `/api/legal-ai/*` 本地规则引擎驱动，读取案件、文档、备注、工时、账单、任务、沟通、客户与法规期限等真实业务数据，输出均为需人工复核的草稿。
- **6 个律师工具箱功能**为独立专用页面（`/tools/*`）：后端 `/api/legal-toolbox/*` 提供本地规则测算与演示数据，所有结果可一键结构化保存到当前案件（`tool_calculations` 实体），并在案件详情「律师工具」页签追溯。

62 个二级功能路由唯一；导航按“精确路径 → 查询参数 → 最长路径 → position”解析，一级模块首页优先指向真实业务页。`?tab=time|expense|invoices` 区分计费页签，`/settings?tab=permissions` 直达角色权限矩阵，`/settings?tab=categories` 直达案例分类；`/` 始终指向工作台，未知路径回退到工作台。

其中 **日程管理** 的 6 个二级功能均为真实可用页面，不依赖通用记录或演示数据：

- **日历管理**：月/周/列表视图、多日历与案件筛选、事件可见性、提醒提前量，支持新建、编辑、完成与删除。
- **截止日期计算**：配置法院规则与节假日，从触发日期生成期限链，触发日期变更后重新计算，周末与节假日自动顺延，可一键生成日程。
- **时效管理**：诉讼时效台账，按起算日与期间自动计算到期日，提供临近到期与逾期预警、状态流转。
- **AI日历辅助**：从法院通知或文档文本中按本地规则识别日期并提取上下文，生成待确认日程草稿，确认后写入真实日历，保留来源可追溯；不调用外部 AI 服务。
- **同步与提醒**：标准 ICS 文件导入/导出，以及事项提醒规则与待发送队列；不连接第三方云服务。
- **日历与计费联动**：列出尚未记录工时的日程，一键生成工时记录并统计已关联工时与金额。

**客户沟通**已参照 5-10 人小律所版文档升级为 M7 统一收件箱：

- **会话聚合**：左侧按案件/客户聚合会话，展示渠道来源、未读数、24 小时未回复与需跟进标记，支持全部/未读/未回复/需跟进筛选与搜索。
- **消息对话视图**：右侧按时间展示客户/我方/内部备注消息气泡，支持标记已回复、需跟进、整段会话归档到案件。
- **统一回复**：回复/内部备注模式切换、渠道选择、8 个消息模板一键套用、本地规则 AI 起草（必须人工核对确认后才允许发送）、模板自定义增删改。
- **风险联动**：工作台显示未回复/需跟进沟通预警、7 天内到期期限与逾期账单；顶部导航显示沟通未读角标。
- **跨模块补强**：时间记录支持开始/停止计时器（实时计时并自动累加工时金额）；任务支持从 5 个办案模板一键生成；账单发送需先审批通过。

**M3 案件中心**补强：案件详情新增「当事人与团队」页签，可维护原告/被告/第三人及主办/协办/助理（1 个案件仅 1 名主办）；案件团队同时决定案件与沟通会话的可见范围，非团队成员不可回复该案件客户消息。

**M4 法律AI**（6 个独立专用页面，后端 `/api/legal-ai/*`，本地规则 + 真实业务数据）：

- **卷宗智能解析**：批量本地导入卷宗文本（不上传服务器）并自动归集案件文档/备注；提取带来源片段的时间线、当事人与委托关系图谱、核心争议焦点与证据缺口，生成案件初筛摘要。
- **智能文书起草与审查**：按本所范本与案件事实，一键生成起诉状、律师函、答辩状、法律意见书初稿；正文可逐段编辑，附引用法条原文与人工核对清单，全部勾选后才可复制或保存草稿；系统不会自动发送文书。
- **合同智能风控审查**：设定买方/卖方/中立立场与谈判强度，按风险等级排序标出风险条款、给出一键替换文本，并检测常见缺失条款；引用法条附原文与有效状态，修订稿由人工比对后采用。
- **法规与类案检索助手**：自然语言提问，结论只引用本地已校验法规库中的法条原文并附有效状态与官方来源；条文不存在或状态非「现行有效」时明确拒绝生成结论，杜绝模型幻觉；同时展示类案要旨线索与关联案件的时效期限。
- **AI洞察**：按统计周期（7/30/90 天）读取真实案件、工时、账单、客户与沟通数据，生成本期 vs 上期经营趋势对比、按「优先级 + 期限临近度」透明加权的待办智能排序、未回复/需跟进/逾期账单项/临期期限/沉默客户/未开票工时风险提示，以及客户活跃度建议；可限定单一案件，可一键保存洞察台账，全部输出为需人工复核的草稿。
- **行政事务助手**：按周期汇总工时、已办任务与对外沟通，生成可编辑的《客户案件周报》（严格过滤内部备注、工时费率与账单金额）；案件筛选贯穿周报全部数据源；从案件期限与文书内容识别到期日，生成日历提醒建议，需逐条人工确认后才加入日历。

**M5 律师工具箱**（6 个独立专用页面，后端 `/api/legal-toolbox/*`，本地规则 + 明确标注的演示数据）：

- **诉讼执行计算器**：诉讼费按《诉讼费用交纳办法》分段累计精确计算，含保全费（5000 元封顶）、仲裁费（本地演示标准）、各地杂费参考与减半规则（简易程序/调解/撤诉）。
- **利息测算器**：迟延履行期间加倍部分债务利息（日万分之一点七五）与 LPR 1/5 年期历史分段计息，支持单利、按年复利、按月复利、手动固定利率与自定义分段。
- **赔偿测算器**：人身损害赔偿、工伤（含一次性伤残/医疗/就业补助与工亡）赔偿，以及劳动经济补偿金 N / N+1 / 2N 与三倍封顶规则，逐项列明计算依据。
- **诉讼期限推算器**：上诉期、举证期、答辩期、申请执行期推算，自动排除周末与法院法定节假日后顺延；节假日数据复用案件中心台账。
- **证据与文档处理**：身份证号/银行卡号/手机号/邮箱的本地正则脱敏（真实可用、原文不上传）、证据目录与连续页码自动编排；OCR 双层 PDF 为批量登记 + 状态占位，明确标注「未真实识别」。
- **企业工商失信速查**：内置虚构演示主体库，展示股权穿透 SVG、涉诉、被执行与限高信息，可导入客户或相对方档案；明确标注「本地演示数据，非实时」，不得作为尽调依据。

每一项测算结果都可通过「一键保存到当前案件」写入结构化 `tool_calculations` 记录（matterId + 工具类型 + 输入参数 + 结果快照 + 创建人），在对应案件详情的「律师工具」页签查看、展开与删除。

**M6 设置与安全**补强：`/settings` 新增「角色权限」矩阵，按角色配置 8 项能力（全所报表、全部案件、账单审批/发送、财务操作、内部备注、用户管理、AI 使用），配置持久化；账单审批、沟通内部备注与 6 项法律 AI 能力均已接入角色校验（`ai.use` 关闭时 AI 端点返回 403）。法律 AI 生成结果可完整保存到对应工作台台账（含编辑后的全文），沟通模板套用时按案件/客户替换占位符，回复草稿仅在写入成功后清空。

**M1 5 张核心报表**：`/reports` 在经营概览之外提供收入、应收、工时、案件、客户 5 张独立报表（后端 `/api/dashboard/core-reports`），包含本月/本季收款、账龄分析、每人本周/本月工时、案件按领域与律师分布、客户收入贡献。

> 律师工具箱中的 LPR 历史值、地区统计指标、仲裁费与地方杂费、企业工商/失信主体库均为本地演示数据，OCR 双层 PDF 不执行真实识别；正式使用必须核对最新官方标准与原始数据。工具结果仅为辅助参考，需人工核对。

> 沟通渠道中的微信/WhatsApp/邮件/SMS/门户为本地统一收件箱演示，不会真正发回原渠道。所有「AI」能力均由本地规则引擎基于本所真实业务数据生成草稿，不调用外部模型或第三方法规库；法条原文来自本地已校验摘录库，仍需人工核对官方文本。演示环境未接入登录，前端以第一位用户身份发起请求，角色权限用于展示与演示校验，不等于真实认证鉴权。集成生态、安全合规、`payment_online` 等功能以本地配置与演示数据承载，开关与参数可真实修改并持久化到当前演示库，但不会发起对第三方系统的调用或认证审计。

首次启动时，后端会自动创建 `data/crm.sqlite` 并填充律师、客户、联系人、案件阶段、案件（含当事人与团队）、线索、任务、文档、时间费用、账单、支付、信托交易、沟通、备注，以及 9 个一级模块、62 个二级功能、8 个消息模板、5 个任务模板、5 角色 × 8 项权限矩阵、10 个案例分类及其默认办理流程；28 个核心业务/工具功能使用真实本地规则或业务数据；其余 32 个功能保留各自专属工作台 schema、演示记录与本地配置，其中法律 AI 6 项与律师工具箱 6 项改由独立专用页面承载（AI 读取真实业务数据，工具箱使用明确标注的演示数据）。删除该文件后重启即可重置。
