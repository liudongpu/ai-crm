# Law Firm OS（5-10 人小律所版）完整产品文档

> 版本：Lite v2.0（完整版，仅 MD）
> 适用：5-10 人律所，1 个办公点，合伙人 1-3 人，律师 + 助理 + 财务 / 行政共 5-10 人
> 依据：Law Firm OS 完整 PRD v2.0 + 业务流程设计文档 + 5-10 人简化版
> 本次更新：新增 **M7 沟通中心**，一个页面对接各种聊天工具，全部归档到案件
> 命名：线索 Lead、客户 Client、案件 Matter、当事人 Party、冲突审查、工时 Time Entry、账单 Invoice、收款 Payment、信托 Trust、沟通记录、任务 Task、期限 Deadline、文档 Document

## 1. 产品定位

### 1.1 小律所的真实痛点

- 人少事多：一个人既办案又跟客户又记工时，没时间学复杂系统。
- 沟通分散：微信、电话、短信、邮件、门户消息各在一处，找聊天记录要翻 5 个 App，关键承诺找不到。
- 案件一多就乱：文档在微信 / 网盘 / 电脑里，期限靠脑子记，账单靠月底突击。
- 收钱慢：工时漏记、账单拖延、客户拖欠，现金流不稳。
- 合伙人看不清：这个月做了多少、收了多少、谁最忙、哪个案件最赚钱，心里没数。

### 1.2 产品目标

| 目标 | 做到什么程度 |
|---|---|
| 沟通不丢 | 一个页面看全部聊天，自动归档到案件，可搜索 |
| 案件不乱 | 打开案件就能看到当事人、文档、任务、期限、沟通、工时、账单 |
| 期限不错过 | 法定期限自动算，提前提醒，逾期有预警 |
| 工时不漏记 | 当天记工时，计时器一键开始 / 暂停 |
| 账单不拖延 | 工时 → 账单草稿 → 审批 → 发送，3 步完成 |
| 收款能看清 | 谁欠钱、欠多少、欠多久，一张表看清 |
| 信托不混同 | 信托与运营分开，每笔有记录，能对账 |

### 1.3 非目标（小团队先不做）

- 不做多律所 / 多分所 / 多组织。
- 不做复杂的自定义工作流、复杂的审批链。
- 不做企业级 API、Webhook、应用市场。
- 不做多币种、多语言、多司法辖区（先做 1 个司法辖区）。
- 不做营销自动化、广告投放、客户生命周期等重营销功能。
- 不做复杂的绩效考核、KPI 排名。
- 不做替代微信 / WhatsApp 本身：沟通中心是聚合与归档，不是再造一个聊天 App。

## 3. M1 工作台与报表

| 功能 | 说明 | 小团队做法 |
|---|---|---|
| 我的工作台 | 待办、今日日程、我的案件、通知 | 每天上班先看工作台 |
| 经营数据 | 收入、应收、案件数 | 合伙人可见，律师可见自己的 |
| 风险预警 | 期限临近、逾期账款、未记工时、未回复消息 | 提前 3 天 / 7 天提醒；未回复客户消息超过 24 小时预警 |
| 快捷新建 | 新建线索、案件、记工时、生成账单、发消息 | 一键直达 |
| 5 张核心报表 | 收入、应收、工时、案件、客户 | 先做这 5 张，够用 |

**5 张核心报表：**

1. 收入报表：本月 / 本季收入、已收 / 未收。
2. 应收报表：谁欠钱、欠多少、欠多久。
3. 工时报表：每人本周 / 本月工时、可计费 / 不可计费。
4. 案件报表：进行中案件数、按类型 / 按律师分布。
5. 客户报表：新增客户数、客户收入贡献。

## 4. M2 获客与客户

| 功能 | 说明 | 小团队做法 |
|---|---|---|
| 线索登记 | 手动 / 网站 / 电话 / 转介绍 | 转介绍为主，手动登记即可 |
| 线索跟进 | 跟进记录、提醒 | 每次跟进写一句话，系统提醒停滞线索 |
| 冲突审查 | 查客户 / 当事人 / 历史案件 | 必须做，未通过不可签约 / 建案 |
| 咨询预约 | 客户选时间，自动发 Intake 表 | 用日历预约即可，不做复杂排期 |
| 签约 | 电子签名 + 预付款 | 签完自动生成客户 + 案件 |
| 客户档案 | 客户信息、联系人、历史 | 一个客户可有多个案件 |
| 客户门户 | 客户看进度、交材料、看账单、付款 | 客户自助，减少律师重复答复；门户消息进 M7 沟通中心 |

**小团队获客流程：** 线索 → 冲突审查 → 咨询 → 签约 → 客户 + 案件。不做复杂的线索评分、营销自动化。

## 5. M3 案件中心

| 功能 | 说明 | 小团队做法 |
|---|---|---|
| 新建案件 | 自动编号、类型、阶段 | 编号规则简单：年份 + 序号 |
| 当事人 | 原告 / 被告 / 第三人 | 角色字段区分 |
| 案件团队 | 主办 / 协办 / 助理 | 1 个案件 1-3 人即可 |
| 任务 | 任务、子任务、截止日期 | 用任务模板，一键生成 |
| 期限 | 法定期限、提醒 | 自动算，提前提醒，逾期预警 |
| 日历 | 个人 / 案件日历 | 与 Google / Outlook 同步 |
| 文档 | 上传、分类、版本、搜索 | 文件夹按案件分，命名规范统一 |
| 电子签名 | 合同 / 委托协议签署 | 签署有审计轨迹 |

**任务模板（小团队先做 3 个）：**

- 民事诉讼：收集证据 → 起草起诉状 → 立案 → 开庭 → 判决 → 执行。
- 劳动仲裁：收集劳动合同 → 收集工资流水 → 整理考勤 → 起草申请书 → 提交 → 开庭。
- 合同审查：收集合同 → 审查条款 → 出具意见 → 修改 → 定稿。

**案件页聚合：** 打开案件就能看到当事人、文档、任务、期限、沟通（来自 M7）、工时、账单。沟通不再需要跳到微信里翻。

## 6. M4 法律 AI

| 功能 | 说明 | 小团队做法 |
|---|---|---|
| 案件摘要 | 按证据生成案件事实摘要 | 打开案件一键生成，需人工核对 |
| 法律检索 | 按事实找法规 / 判例 | 结果可打开原文 |
| 文书生成 | 起诉状 / 答辩状等 | 生成后必须人工审核 |
| 文书润色 | 语言、逻辑优化 | 原文保留，改动高亮 |
| 合同审查 | 风险条款排序 | 按风险等级看，先看高风险 |
| 文档问答 | 按案件材料回答问题 | 回答标注来源 |
| 邮件 / 消息起草 | 起草客户邮件 / 聊天回复 | 需人工确认后发送；见 M7 |

**AI 硬规则（小团队也要守）：**

- AI 只能看有权限的案件与文档。
- AI 输出是草稿，不可直接发给客户 / 提交法院，必须人工确认。
- AI 提的期限，必须人工确认后才落入正式日历。
- 客户信息不用于训练第三方 AI 模型。

## 7. M5 计费财务

| 功能 | 说明 | 小团队做法 |
|---|---|---|
| 记工时 | 手动 / 计时器 | 当天记，计时器一键开始 / 暂停 |
| 费率 | 人员费率、案件费率 | 每人 1 个费率，特殊案件单独设 |
| 费用 | 交通、差旅、材料费 | 拍照上传收据 |
| 计费方式 | 按小时 / 固定 / 分阶段 / 预付 | 先做按小时 + 固定，够用 |
| 生成账单 | AI 起草、标记缺失时间 | 草稿可预览 |
| 账单审批 | 合伙人审批 | 审批前不可发送 / 入账 |
| 发送账单 | 邮件 / 门户 | 发送后状态自动更新；发送记录进 M7 |
| 收款 | 卡 / eCheck / 门户支付 | 支付成功后自动更新账单 |
| 支付计划 | 分期 | 客户分期需合伙人确认 |
| 信托 | 信托账户、信托收支、信托对账 | 信托与运营分开，见 7.1 |
| 财务报表 | 收入、支出、利润 | 每月 1 张，合伙人看 |

### 7.1 信托（小团队版，3 条硬规则）

1. **分开**：信托账户与运营账户分开，绝不混同。
2. **审批**：信托支出必须合伙人审批，无审批不支出。
3. **对账**：每月对账一次，银行记录 = 客户台账 = 信托负债，不一致立即处理。

```text
客户资金存入信托账户 → 按客户记明细账
  → 需要支出 → 合伙人审批 → 支出
  → 每月对账 → 一致 → 保留报告
  → 不一致 → 立即处理，不拖到下个月
```

## 9. M7 沟通中心（新增）

### 9.1 一句话

**一个页面，对接各种聊天工具。**

律师不用再在微信、WhatsApp、短信、邮件、电话、门户消息之间来回切换。所有沟通进一个收件箱，按客户 / 案件聚合，自动归档，可搜索，可直接回复。

### 9.2 沟通中心页面长什么样

```text
┌─────────────────────────────────────────────────────────────┐
│ 沟通中心                                                      │
│ [搜索：客户 / 案件 / 关键词]  [筛选：未回复 / 我负责 / 需跟进] │
├──────────────┬──────────────────────────────────────────────┤
│ 左：会话列表  │ 右：会话详情                                  │
│ 按客户 / 案件 │ 顶部：客户 + 案件 + 渠道标签                  │
│ 聚合显示      │ 中间：全部消息按时间合并（微信 + 邮件 + 短信）  │
│ 未读数        │ 底部：回复框 + 模板 + AI 起草 + 发文档 / 发账单 │
│ 未回复提醒    │ 右侧：案件卡片（当事人 / 期限 / 账单 / 文档）   │
└──────────────┴──────────────────────────────────────────────┘
```

### 9.3 对接的聊天工具

| 渠道 | 对接方式 | 小团队做法 |
|---|---|---|
| 微信 | 微信客服 / 企业微信 / 微信扫码绑定（按可用合规方式） | 先做 1 个律所微信号聚合；个人微信手动转发归档兜底 |
| WhatsApp | WhatsApp Business API | 有涉外客户时开 |
| 短信 SMS | 短信服务商 | 验证码 / 提醒 / 催款用 |
| 邮件 Email | Gmail / Outlook 同步 | 邮件自动归档到案件 |
| 电话 | 电话集成 / 通话记录 | 通话后自动生成通话记录，可写摘要 |
| 客户门户消息 | 门户内置消息 | 客户在门户发的消息进同一收件箱 |
| 视频会议 | Zoom / Teams | 会议链接进日历，会议纪要进案件 |
| 内部消息 | 团队内部备注 | 内部备注不对外可见，与客户消息分开 |

> 说明：微信个人号、企业微信、WhatsApp 的具体对接能力受平台政策与合规要求限制。实施时以各平台官方开放能力与律所合规意见为准。个人微信无法自动同步时，用“转发归档”兜底：律师转发关键消息到律所微信号 / 上传截图，手动选案件归档。

### 9.4 核心功能

| 功能 | 说明 | 验收标准 |
|---|---|---|
| 统一收件箱 | 微信、WhatsApp、短信、邮件、门户消息、电话记录进一个页面 | 一个页面能看到全部渠道消息，不用来回切换 App |
| 按客户 / 案件聚合 | 同一个客户 / 案件的全部消息合并成一个会话 | 打开客户或案件，能看到全部沟通历史 |
| 自动归档 | 消息按客户 / 案件自动归档 | 归档准确率可抽查；归档错误可手动纠正 |
| 手动归档 | 无案件消息可手动选案件归档 | 手动归档 2 步完成 |
| 直接回复 | 在沟通中心直接回复，不跳 App | 回复后原渠道客户能收到（支持的渠道） |
| 未回复提醒 | 超过 24 小时未回复预警 | 未回复列表可筛选 |
| 需跟进标记 | 标记需跟进，自动进待办 | 标记后工作台待办同步 |
| 沟通搜索 | 按客户 / 案件 / 关键词 / 日期搜索 | 搜索能找到关键承诺与金额 |
| 消息模板 | 常用回复模板 | 模板可自定义，见 9.5 |
| AI 起草回复 | AI 按案件信息起草回复 | 需人工确认后发送，不可自动发送 |
| 发文档 / 发账单 | 在会话里直接发文档 / 账单 | 发送记录自动归档到案件 |
| 通话记录 | 电话后自动生成记录 | 可写摘要，可转任务 |
| 会议纪要 | 会议后生成纪要 | 纪要需人工确认后发送 |
| 内部备注 | 团队内部讨论 | 内部备注不对外可见，与客户消息严格分开 |
| 敏感内容保护 | 内部备注、未审核 AI 输出、未发送账单草稿不可对客户可见 | 越权测试通过 |
| 消息审计 | 谁、何时、发了什么、发给谁 | 审计日志不可删除 |

### 9.5 消息模板（小团队先做 8 个）

| 模板 | 用途 |
|---|---|
| 收到材料确认 | “已收到您的材料，正在处理。” |
| 咨询预约确认 | “已预约 X 月 X 日 X 时咨询，地点 / 链接如下。” |
| 委托协议已发送 | “委托协议已发送，请查看并签署。” |
| 预付款提醒 | “请按协议支付预付款，金额 X，账号如下。” |
| 账单已发送 | “账单已发送，请查看，付款链接如下。” |
| 催款 | “账单已逾期 X 天，请尽快支付。” |
| 开庭提醒 | “开庭时间 X 月 X 日 X 时，地点 X，请携带证件。” |
| 案件进展更新 | “案件最新进展如下，下一步是 X。” |

### 9.6 沟通流程

```text
客户发消息（微信 / WhatsApp / 短信 / 邮件 / 门户）
  → 进入沟通中心统一收件箱
  → 自动匹配客户 / 案件
      ↳ 匹配成功 → 自动归档到案件
      ↳ 匹配失败 → 手动选客户 / 案件归档
  → 未回复提醒（超过 24 小时）
  → 律师回复
      ↳ 直接回复 / 用模板 / AI 起草后人工确认
  → 回复自动归档到案件
  → 需要跟进？ → 标记需跟进 → 自动进待办 / 生成任务
```

### 9.7 沟通与案件 / 账单的联动

| 场景 | 联动 |
|---|---|
| 客户问案件进展 | 右侧案件卡片显示进度、期限、下一步，一键发进展模板 |
| 客户问费用 | 右侧显示账单状态，一键发账单 / 付款链接 |
| 客户发新材料 | 消息里收到的文档一键存到案件文档 |
| 客户约时间 | 消息里约的时间一键生成日历事件 / 咨询预约 |
| 客户承诺付款 | 消息标记为承诺，自动生成催款提醒 |
| 内部讨论 | 内部备注不进客户会话，单独显示 |

### 9.8 沟通合规与风险

- **留痕**：所有对外消息有记录，不可删除，不可篡改。
- **授权**：只有案件团队成员可回复该案件的客户消息；非团队成员不可见。
- **敏感信息**：不在聊天里发完整账号、密码、敏感证件；必要时走门户文档。
- **AI 回复**：AI 起草的回复必须人工确认后发送，不可自动发送给客户。
- **微信合规**：遵守微信 / WhatsApp 平台规则与律所合规意见；不做违规自动群发、违规外挂。
- **客户隐私**：客户消息不用于训练第三方 AI 模型。

## 10. 业务流程（4 条）

### 10.1 流程 A：获客 → 委托

```text
线索进入（转介绍 / 电话 / 网站）
  → 创建线索
  → 冲突审查
      ↳ 通过 → 咨询预约
      ↳ 不通过 → 拒绝委托，记录原因
  → 咨询（预约 + 记录，沟通进 M7）
  → 接受委托？
      ↳ 是 → 签约（电子签名 + 预付款）
      ↳ 否 → 记录原因，结束
  → 自动生成客户 + 案件
  → 分配团队，结束
```

**小团队要点：** 冲突审查不能省，哪怕只有 5 个人，也要查。转介绍也要查。

### 10.2 流程 B：办案

```text
建案
  → 分配团队 + 权限
  → 上传材料
  → 任务模板一键生成任务 + 期限
  → 办案执行（循环）
      ↳ 做任务
      ↳ 跟期限
      ↳ 处理文档
      ↳ 跟客户沟通（M7 沟通中心）
      ↳ AI 摘要 / 起草（需人工审核）
      ↳ 记工时 / 记费用
  → 客户沟通（门户更新 / M7 回复）
  → 结案检查 → 结案审批 → 归档
```

**结案检查（小团队版，4 项）：**

- [ ] 任务都完成了？
- [ ] 账单都结清了？
- [ ] 文档都归档了？
- [ ] 信托余额处理了？（退款 / 转运营，需审批）

### 10.3 流程 C：计费 → 收款

```text
配置计费方式（按小时 / 固定）
  → 每天记工时 / 记费用
  → 月底生成账单草稿
  → 合伙人审批
      ↳ 通过 → 发送账单（邮件 / 门户 / M7）
      ↳ 驳回 → 修改后重新提交
  → 客户支付
      ↳ 成功 → 入账，更新应收
      ↳ 失败 → 重试 / 催款（M7 催款模板）
  → 催款（逾期自动提醒）
```

**小团队要点：** 工时当天记，不要月底补记。账单月底发，不要拖到下个月。

### 10.4 流程 D：沟通（新增，贯穿全部流程）

```text
客户发消息（任意渠道）
  → M7 沟通中心统一收件箱
  → 自动归档到案件
  → 律师回复（直接 / 模板 / AI 起草后确认）
  → 需要跟进 → 生成任务 / 待办
  → 需要发文档 / 账单 → 在会话里直接发
  → 沟通记录自动进案件时间线
```

**沟通流程要点：** 沟通不是单独的流程，而是贯穿获客、办案、计费的“毛细血管”。任何流程里的沟通，都要在 M7 里有记录，在案件里能找到。

## 11. 角色与权限

### 11.1 4 个角色

| 角色 | 人数示例 | 能做什么 | 不能做什么 |
|---|---|---|---|
| 合伙人 | 1-3 人 | 看经营报表、审批账单 / 结案 / 信托、管理用户 | 不能看非团队案件的敏感内容（除非授权） |
| 律师 | 2-5 人 | 办案、记工时、生成账单草稿、跟客户沟通（M7） | 不能审批自己的账单（需合伙人审批） |
| 助理 | 1-2 人 | 做任务、上传文档、跟进日历、整理材料、回复常规消息（需授权） | 不能看财务数据、不能发账单 |
| 财务 / 行政 | 1 人（可兼） | 收款、对账、信托、报表 | 不能看非必要案件内容 |

### 11.2 权限规则（小团队版）

- 只能看自己团队的案件，合伙人可看全部（但敏感内容仍需授权）。
- 沟通权限：只有案件团队成员可回复该案件的客户消息；非团队成员不可见该会话。
- 账单审批：律师生成草稿，合伙人审批，审批前不可发送。
- 信托：只有财务 + 合伙人可操作。
- 离职交接：交接完再禁用账号，原用户不可再访问已交接案件与会话。

## 12. 数据与迁移

### 12.1 数据迁移（小团队版）

| 数据 | 做法 |
|---|---|
| 客户 | Excel 导入，导入前去重 |
| 案件 | 导入进行中案件，已结案案件可只导基本信息 |
| 文档 | 按案件文件夹批量上传 |
| 工时 / 账单 | 导入本年度数据，历史数据可只导汇总 |
| 联系人 | 随客户一起导入 |
| 沟通记录 | 导入近 3 个月关键沟通（邮件 / 门户），微信历史手动归档关键消息即可，不追求全量导入 |

### 12.2 数据规范（小团队版）

- 案件编号：年份 + 序号，例如 2026-001。
- 文档命名：案件编号 + 文档类型 + 日期，例如 2026-001-起诉状-20260101。
- 客户命名：个人用全名，企业用全称，不用简称。
- 工时记录：当天记，写清楚做了什么，不要只写“办案”。
- 沟通归档：每条对外沟通必须有案件归属，无案件的先归到客户，再补案件。

## 13. 上线计划（2 周可用）

| 周 | 任务 | 负责人 |
